# 行人相对赛道远离判定设计

## 背景

当前行人远区停车和拉线主要使用检测框中心的固定屏幕坐标区间。智能车向前行驶、进入弯道或相机视角变化时，即使行人与赛道的实际横向关系没有改变，行人脚点仍可能在画面中向左下或右下移动。这会把车辆自运动和透视变化误当成行人横向运动，造成错误停车、错误释放或绕行方向抖动。

现有系统已经具备行人脚点、脚点区域、赛道左右边界、AI 新源帧控制和 `StopInTrack -> DetourOutside -> FAST` 状态链。本设计复用这些能力，不引入地面坐标标定或多目标跟踪。

## 目标

- 智能车位于赛道内时，不再用行人的绝对屏幕 X/Y 决定 STOP 释放。
- 首次发现满足深度条件的行人时先 STOP。
- 只有连续的新 AI 源帧证明行人位于赛道安全带之外并持续远离，才允许锁定反向绕行线。
- 保留现有第二级拉线有效性确认；拉线持续有效后才发送 FAST。
- 智能车位于赛道外时完整沿用当前屏幕坐标判断，兼容出赛道吃金币、赛道缺失和赛道大角度倾斜的场景。
- `EVID REUSE` 和 `EVID UNK` 不推进任何高影响行人状态。

## 已确认约束

- 比赛场景不会同时出现多名行人，因此本次只维护一个行人风险目标，不增加多目标身份管理。
- `personStopReleaseConfirm` 继续作为远离确认帧数；当前配置值为 3。
- `personDetourFastConfirm` 继续作为拉线有效性确认帧数；当前配置值为 2。
- 远离确认后采用方案 B：先锁定反向拉线并继续 STOP，拉线确认完成后再发送 FAST。
- 行人判断不改变车辆、金币、路牌和 0x02 运动模式仲裁的既有优先级。

## 双路径判断架构

每个可推进状态的行人新源帧，根据现有 `car_track_relation_inside` 选择且只选择一条路径：

```text
                                  car_track_relation_inside
行人目标 + EVID NEW ─────────────────────┬─────────────────────
                                        │
                               true     │     false
                                        │
                         TrackRelative  │  ScreenCoordinate
                         相对边界趋势判断   当前屏幕坐标判断
```

### TrackRelative：车在赛道内

满足 `score > 0.30` 且 `center_y > personAvoidMinY` 的行人第一次出现时，由于尚无趋势证据，立即进入或保持 `StopInTrack`。此路径不调用当前远区/近区绝对坐标释放规则。

状态机只可能通过本文定义的相对边界远离确认进入 `DetourOutside`。行人位于赛道内、橙色安全带内、区域未知或边界不可靠时始终保持 STOP。

### ScreenCoordinate：车在赛道外

完整保留当前 `tcPedEvalEmerg()` 远区和近区坐标规则、停车锁、释放确认及拉线方向逻辑。本设计不改变这些阈值或分支顺序。

`car_track_relation_inside` 继续由 `carTrackRelationY` 行的赛道中点相对画面中心误差决定。赛道中点无效时 `getMidX()` 返回负值，结果自然落入赛道外路径，符合看不到赛道时使用坐标判断的要求。

### 路径切换

保存上一有效判断路径。`TrackRelative` 与 `ScreenCoordinate` 发生切换时清空相对距离历史，禁止跨路径复用样本。

如果行人已经进入 `DetourOutside`，继续执行现有绕行线锁定行为，直到行人按现有消失规则退出；不因单帧车道内外判断变化而翻转绕行方向。路径切换只影响尚未进入绕行的 STOP/Idle 决策。

## 相对边界样本

### 边界可靠性

在脚点所在行解析原始左右赛道边界 `lx`、`rx`，并使用现有透视扩宽计算得到橙色安全带外沿 `lx_ex`、`rx_ex`。

用于释放确认的边界必须满足：

- `rx > lx`；
- 赛道宽度有效；
- 左右边界必须来自脚点所在的同一图像行；
- 扩宽后的 `lx_ex < rx_ex`。

脚点同行找不到有效边界时，本帧区域按 `Unknown` 处理：清空远离历史并保持 STOP。现有区域可视化仍可继续使用向上搜索的宽松边界回退，但跨行结果不能作为 STOP 释放证据。

### 安全带外侧距离

只有脚点位于安全带外侧时才产生距离样本：

```text
OUT_L: clearance = (lx_ex - foot_x) / max(1, rx - lx)
OUT_R: clearance = (foot_x - rx_ex) / max(1, rx - lx)
```

`clearance` 使用脚点同行的赛道宽度归一化。针孔投影下，同一行的横向像素距离和赛道像素宽度具有相同透视缩放因子，因此比值可抵消赛道梯形和车辆靠近造成的一阶缩放。禁止把其他图像行的边界与当前脚点混算；`TRACK`、`ORG_L`、`ORG_R` 和 `Unknown` 均不是可释放样本。

## 连续远离确认

新增单目标运行状态 `PedRelativeAwayState`，至少保存：

- 上一判断路径；
- 当前外侧 `OUT_L` 或 `OUT_R`；
- 最近的归一化 `clearance` 样本；
- 当前有效确认计数；
- 最近脚点，用于识别不可信的检测跳变。

只在 `EVID NEW` 时更新该状态。`EVID REUSE` 和 `EVID UNK` 保持现有离散状态、历史和计数不变。

有效确认帧数为：

```text
confirm_required = max(3, personStopReleaseConfirm)
```

至少需要 3 个样本才能判断趋势。当前配置为 3，因此实际行为不变。

一个完整窗口必须同时满足：

1. 所有样本都来自 `TrackRelative` 路径；
2. 所有样本都属于同一侧 `OUT_L` 或同一侧 `OUT_R`；
3. 最后一个样本减第一个样本不小于 `personAwayMinGrowthRatio`；
4. 任意相邻样本允许的反向抖动不超过 `personAwayMinGrowthRatio / 2`；
5. 相邻归一化距离的绝对跳变不超过 0.50；超过时视为检测框跳变，重新开始确认；
6. 窗口内没有出现 `TRACK`、橙色区域、`Unknown`、边界失效、侧别变化、目标缺失或判断路径变化。

新增配置：

```json
"personAwayMinGrowthRatio": 0.04
```

默认要求确认窗口内的净远离量至少达到当前赛道宽度的 4%，允许单步最多反向抖动 2%。只增加净增长配置，抖动容差由其派生，避免两个高度相关的调参项。

任一条件不满足时清空窗口并保持 STOP。当前帧若仍是有效的同侧 `OUT` 样本，可以作为新窗口的第一个样本，避免因为一次轻微回摆额外丢失一整帧。

## 状态机与指令时序

车在赛道内时，处理顺序调整为：

1. 对 `EVID REUSE/UNK` 沿用现有入口保持逻辑并返回；
2. 获取行人脚点并选择判断路径；
3. `TrackRelative` 路径先更新相对远离状态；
4. 未完成远离确认时立即进入或保持 `StopInTrack`，发送行人 STOP 请求；
5. 完成远离确认时，根据确认侧锁定反向绕行线，调用现有 `tcPedEnterDetour()`；
6. 进入绕行会清除 `g_person_stop_lock`，但不会立即发送 FAST；
7. 继续由现有 `tc_syncPedDetourUart()` 从首次有效锁线帧开始累计 `personDetourFastConfirm`；累计达到 2 个可推进的新源帧后发送 FAST。

相对远离判断必须位于 `g_person_stop_lock` 的提前返回之前。否则当前 10 帧停车锁会覆盖已经确认的 3 帧释放证据。只有相对路径确认成功才允许绕过并清除停车锁；赛道外坐标路径继续沿用当前停车锁行为。

反向拉线方向在进入 `DetourOutside` 时锁定：左侧行人向右绕，右侧行人向左绕。后续单帧脚点变化不允许翻转已锁定方向。

## 异常和降级处理

- 脚点越界、赛道宽度无效、扩宽失败或脚点同行边界缺失：按 `Unknown` 处理，清空确认并保持 STOP。
- 行人脚点从画面一侧突然跳到另一侧：清空确认并保持 STOP。
- 相邻归一化距离跳变超过 0.50：视为检测异常，不用于解除 STOP。
- 行人目标按现有 `aiSourceExitConfirmFrames` 确认消失后，继续执行现有退出逻辑；本设计不延长目标消失停车时间。
- 赛道内外判定抖动：每次切换都清空相对历史；已锁定绕行不受影响。
- 赛道外或赛道不可见：进入 `ScreenCoordinate` 路径，不尝试从不可靠边界计算趋势。

## 调试可视化

行人 HUD 增加以下字段：

```text
judge=REL|XY side=L|R|? clr=<ratio> away=<count>/<required> bnd=OK|BAD
```

- `REL` 表示相对赛道判断，`XY` 表示当前屏幕坐标判断；
- `clr` 仅在相对样本有效时显示；
- `away` 只随不同的 `EVID NEW` 推进；
- `bnd=BAD` 明确说明保持 STOP 是因为边界不足，而不是坐标阈值命中。

现有 `PED ph`、绕行侧、释放计数和 0x02 HUD 保留。原始屏幕 X 方向拟合可继续作为诊断信息，但不得参与 `TrackRelative` 决策。

## 测试设计

扩展 `test/test_ped_source_driven_control.cpp` 的测试夹具，使每帧可以设置左右边界、边界有效行、车道中点偏移、脚点和 AI evidence。

至少覆盖以下场景：

1. 车在赛道内，行人首次出现在安全带外：当前帧进入 `AvoidPed/StopInTrack` 并发送 STOP。
2. 行人屏幕脚点向左下移动，但归一化外侧距离不增长：始终 STOP。
3. 同侧 `OUT` 的归一化距离连续满足 3 帧趋势：进入 `DetourOutside`、锁定反向拉线，但仍发送 STOP。
4. 从首次锁线帧起累计 2 个有效新源帧：才发送 FAST。
5. `EVID REUSE/UNK` 不增加、不清零远离计数和拉线确认计数。
6. 任一帧进入 `TRACK`、`ORG_L/R` 或 `Unknown`：远离确认清零并保持 STOP。
7. 脚点同行边界无效，即使上方相邻行存在边界：保持 STOP。
8. `OUT_L` 与 `OUT_R` 切换、净增长不足、反向抖动超限或距离突跳：不得释放 STOP。
9. `TrackRelative -> ScreenCoordinate` 和反向切换：相对历史清零，不跨路径累计。
10. 车在赛道外时，现有远区 STOP、远区拉线、近区 STOP/拉线及停车锁测试结果不变。
11. 进入 `DetourOutside` 后车道内外判定变化：绕行侧和已锁定拉线保持不变。
12. 行人 STOP、等待 FAST、FAST 请求经 0x02 批处理仲裁后，HUD 与实际发送模式保持同帧一致。

相关回归包括行人 source-driven、行人/车辆冲突、金币慢行、车辆/金币 source-driven、删除元素和运动模式仲裁测试。

## 验收标准

- 实车靠近静止或沿赛道外侧移动的行人时，单纯的屏幕左下/右下漂移不能解除 STOP。
- 行人相对安全带持续远离 3 个新源帧后才锁定反向绕行线。
- 拉线从首次有效帧累计满 2 个新源帧后才发送 FAST。
- 行人进入或靠近安全带、边界不可靠、证据复用或坐标突跳时，不会误释放 STOP。
- 智能车在赛道外、赛道不可见或明显倾斜时，行人判断与当前坐标逻辑一致。
- 0x02 HUD 显示与实际发送结果一致，并保留行人 STOP 的最高安全优先级。

## 非目标

- 不引入相机地面标定、真实速度估计或 TTC 计算。
- 不实现多行人身份跟踪或多目标风险融合。
- 不改变智能车在赛道外时的行人坐标阈值。
- 不修改金币出赛道、返回赛道、车辆避让或路牌状态机。
- 不调整 0x02 仲裁优先级。
